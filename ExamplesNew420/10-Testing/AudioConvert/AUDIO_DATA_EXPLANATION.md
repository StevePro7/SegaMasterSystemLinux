# Where Is the Actual Audio Data?

## Quick Answer

**The actual music and sound data IS in `audio_data.h`!** 

The extraction script converted all the hex values from the original z80 assembly into C byte arrays. Here's exactly what happened:

---

## The Complete Flow

### Step 1: Original Assembly (Binary Data)
```asm
; TransbotASM/content/psg_data.inc
_DATA_3531_:
	.db $03 $80 $20 $04 $4F $35 $DF $00 $10 $0D $80 $21 $04 $4D $35 $DF
	.db $00 $10 $0B $80 $23 $04 $76 $35 $0F $00 $06 $0C $80 $03 $80 $3C
	; ... (132 bytes total for Track 0)
```

### Step 2: Extraction Script Converts It
The `extract_audio_data.py` script reads this assembly and converts to C:

```
Input:  .db $03 $80 $20 $04 $4F $35 $DF $00 ...
         ↓
         Python script converts $ (hex) to 0x format
         ↓
Output: 0x03, 0x80, 0x20, 0x04, 0x4F, 0x35, 0xDF, 0x00, ...
```

### Step 3: Output in C Header
```c
// TransbotCnew/dev/engine/audio_data.h (generated)
const uint8_t MUSIC_TRACK_0[] = {
    0x03, 0x80, 0x20, 0x04, 0x4F, 0x35, 0xDF, 0x00, 0x10, 0x0D, 0x80, 0x21, 0x04, 0x4D, 0x35, 0xDF,
    0x00, 0x10, 0x0B, 0x80, 0x23, 0x04, 0x76, 0x35, 0x0F, 0x00, 0x06, 0x0C, 0x80, 0x03, 0x80, 0x3C,
    // ... 132 bytes total ...
};
```

## Why Two Files?

### `audio_data.h` - Contains the actual data
```c
// This is WHERE the data IS
const uint8_t MUSIC_TRACK_0[] = {
    0x03, 0x80, 0x20, 0x04, 0x4F, 0x35, 0xDF, 0x00,
    // ... actual bytes from original game ...
};
```

### `audio_manager.c` - Uses the data
```c
// This is HOW we use the data
#include "audio_data.h"  // ← Brings in all the MUSIC_TRACK_* arrays

static const uint8_t *music_tracks[NUM_MUSIC_TRACKS] = {
    MUSIC_TRACK_0,  // ← Points to the data in audio_data.h
    MUSIC_TRACK_1,
    MUSIC_TRACK_2,
    // ... etc ...
};

bool audio_play_music(uint8_t track_id, uint8_t loop_count) {
    const uint8_t *track_data = music_tracks[track_id];  // Get the data
    PSGPlayLoops(track_data, loop_count);  // Pass to PSGlib
}
```

## How It All Works Together

```
1. Run extraction script:
   python3 extract_audio_data.py TransbotASM/content/psg_data.inc TransbotCnew/dev/engine/audio_data.h

2. Script generates audio_data.h with all music/frequency/envelope data

3. audio_manager.c includes audio_data.h:
   #include "audio_data.h"

4. When game needs music:
   audio_play_music(MUSIC_TRACK_GAMEPLAY, 0xFF);
   ↓
   This fetches MUSIC_TRACK_2 from audio_data.h
   ↓
   Sends the 374 bytes to PSGlib
   ↓
   PSGlib plays the data frame by frame
   ↓
   ♪ ♪ ♪ Music plays through SMS speaker!
```

## Why This Design?

### ✅ Benefits:
1. **Separation of concerns**: Data separate from code
2. **Easy regeneration**: Just re-run script if audio changes
3. **Easy identification**: Track names are descriptive
4. **Compiler optimizes**: Data stored in ROM, not RAM
5. **Portable**: Works with any C compiler (SDCC, GCC, etc.)

### ❌ What NOT to do:
- ❌ Don't manually edit audio_data.h (regenerate instead)
- ❌ Don't modify the extraction script without understanding the format
- ❌ Don't forget to include audio_data.h in audio_manager.c
